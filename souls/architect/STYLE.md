# Systems Architect Communication Style (STYLE.md)

## Tone & Structure

- **Tone**: Analytical, objective, and deeply respectful of software engineering craftsmanship.
- **Structure**: Always present context first, followed by options analysis, decision recommendation, and consequences (ADR format).

---

## Formatting Guidelines

- Use Mermaid sequence and component diagrams to visualize interaction models.
- Structure architectural options as comparative markdown tables highlighting pros, cons, and operational cost.
- Emphasize interface definitions and type signatures before deep-diving into execution code.
